# Pipeline Methodology Overview (Descriptive)

This document paraphrases the original the original methodology document without mentioning internal function names. It describes the data flow and processing steps in words only.

## Sex Classification Pipeline (English)
The workflow begins by loading the raw CSV tables. During this stage, the column names are harmonised and numeric columns are converted so that all tables have a consistent structure. The cleaned versions are saved for later use.
Before any modelling takes place, the combined dataset is carefully screened. Each entry is inspected for missing or contradictory information, with suspicious values flagged. Where possible, measurement units are harmonised to avoid discrepancies between datasets from different collection campaigns. This step is essential for ensuring that the later stages of the pipeline operate on consistent input.

After cleaning, the footprints belonging to each individual are grouped together. These groups are then split by species into separate training and testing files. If required, an additional inference set is created. The splitting procedure ensures that every individual appears in only one of the sets, keeping the proportion of male and female footprints balanced. When cross-validation is enabled, an equal number of folds is drawn so that each fold has a comparable sex ratio.
To guarantee reproducibility, the random generator is seeded with a fixed value. Once the train, test and inference sets are formed, their definitions are persisted so that subsequent experiments can reload the same partitions. This practice helps to maintain a stable evaluation environment and eliminates potential data leakage.

For model preparation a scikit-learn `Pipeline` is assembled from several optional components. Missing values can be imputed with a random forest based iterative method. Outliers may be handled either by clipping extreme values or by winsorising according to a z-score threshold. Features are scaled using either standard or robust scaling. Dimensionality reduction is supported via PCA, UMAP or t-SNE, and the feature set can be narrowed down through techniques such as forward selection, random-forest importance, variance thresholding, univariate tests or the LASSO. In the final step one of several classifiers, for example logistic regression, support vector machines or gradient boosting, is added to the pipeline.

Each optional component can be toggled on or off to explore a large number of combinations. Hyperparameters for imputation, outlier treatment, scaling and dimensionality reduction are tuned through systematic searches. By logging these choices in detail, researchers can later reconstruct how a particular result was obtained.
During training the prepared pipeline is applied to each species separately using five-fold cross-validation. Balanced accuracy serves as the evaluation metric. The processing time of each configuration is measured and both the accuracies and the chosen hyperparameters are recorded for later inspection. Afterwards every configuration is refitted on the entire training data and stored with `joblib` for reuse. The best model for each species is stored separately so that predictions can be made easily.

In addition to balanced accuracy, further metrics such as precision, recall and F1 score can be calculated. Timing information is captured to assess computational efficiency, while plots of cross-validation performance give insights into variance across folds. These records form the basis for comparing different modelling strategies.
Reproducibility is supported by caching intermediate results, saving split files in the Parquet format and relying on a globally fixed random seed. The resulting metrics can be compared with related literature on sex classification using gait characteristics, such as the classical works on PCA and the LASSO.

Finally, the full set of results can be exported in tabular form and compared with earlier studies. This ongoing comparison provides context for improvements and helps determine whether certain preprocessing choices lead to more generalisable models.
## Methodik: Sex-Klassifikations-Pipeline (Deutsch)
Der Arbeitsablauf beginnt damit, dass die Rohdaten  eingelesen werden. Dabei werden die Spalten vereinheitlicht und numerische Felder so umgewandelt, dass alle Tabellen das gleiche Format besitzen. Die bereinigten Dateien werden für eine spätere Verwendung gespeichert.

Vor der eigentlichen Aufteilung wird der Datensatz eingehend geprüft. Fehlende Einträge oder widersprüchliche Werte werden markiert und soweit möglich bereinigt. Außerdem werden die Maßeinheiten vereinheitlicht, damit die Daten aus verschiedenen Sammlungen vergleichbar sind.
Im Anschluss werden die Spuren jedes Individuums zusammengefasst und pro Tierart in Trainings-, Test- und optional Inferenzsätze aufgeteilt. Dabei wird darauf geachtet, dass ein Individuum nur in einem dieser Sätze vorkommt und dass das Verhältnis der Geschlechter ausgewogen bleibt. Bei Bedarf werden zusätzlich gleichmäßige Folds für eine Kreuzvalidierung erzeugt.

Um die Reproduzierbarkeit zu gewährleisten, wird der Zufallsgenerator mit einem festen Wert initialisiert. Die so erzeugten Trainings- und Testsätze werden dauerhaft gespeichert, sodass spätere Experimente auf denselben Daten aufbauen können.
Für das Modell wird eine scikit-learn-Pipeline aus mehreren optionalen Bausteinen zusammengesetzt. Fehlende Werte können mit einer iterativen Methode auf Basis von Random Forests imputiert werden. Ausreißer lassen sich entweder durch Clipping extremer Werte oder mittels Winsorisieren nach einem Z-Score-Kriterium behandeln. Die Merkmale werden wahlweise standardisiert oder robust skaliert. Zur Dimensionsreduktion stehen PCA, UMAP und t-SNE zur Verfügung. Die Auswahl relevanter Merkmale kann über Forward Selection, die Bedeutung im Random Forest, einen Varianzschwellenwert, univariate Tests oder die Lasso-Regression erfolgen. Abschließend wird einer von mehreren Klassifikatoren wie logistische Regression, Support Vector Machines oder Gradient Boosting verwendet.

Jeder Baustein der Pipeline lässt sich ein- oder ausschalten, wodurch zahlreiche Kombinationen möglich sind. Die gewählten Parameter für Imputation, Ausreißerbehandlung, Skalierung und Dimensionsreduktion werden systematisch protokolliert, damit sich alle Ergebnisse nachvollziehen lassen.
Beim Training wird diese Pipeline für jede Tierart separat mit einer fünffachen Kreuzvalidierung ausgewertet. Als Kennzahl dient die Balanced Accuracy. Die Laufzeiten der einzelnen Schritte werden erfasst und gemeinsam mit den erzielten Ergebnissen sowie den gewählten Hyperparametern  gespeichert. Anschließend wird jede Konfiguration auf den vollständigen Trainingsdaten erneut trainiert und per `joblib` gespeichert; das jeweils beste Modell wird zusätzlich separat abgelegt, um Vorhersagen zu erleichtern.

Neben der Balanced Accuracy werden weitere Kennzahlen wie Präzision, Recall und F1-Score bestimmt. Durch Aufzeichnen der Laufzeiten kann zudem abgeschätzt werden, wie ressourcenintensiv die verschiedenen Einstellungen sind. Grafische Auswertungen der Kreuzvalidierung zeigen, wie stabil die Modelle über die Folds hinweg sind.
Die Reproduzierbarkeit wird durch Caching von Zwischenergebnissen, das Speichern der Splits im Parquet-Format und einen global festgelegten Zufallssamen unterstützt. Die Messwerte lassen sich mit früheren Arbeiten zur Geschlechtsklassifikation anhand der Gangmerkmale vergleichen, etwa jenen zu PCA oder der Lasso-Regression.

Abschließend lassen sich sämtliche Resultate in Tabellenform exportieren und mit früheren Untersuchungen vergleichen. So wird sichtbar, welche Schritte besonders zum Erfolg beitragen und welche Ansätze weniger robust sind.
## Pairwise Individual Identification Pipeline (English)
This pipeline evaluates whether two movement trails originate from the same individual. Trails may be supplied directly or generated as sliding windows for each animal. Pairs are formed both within and across individuals, labelled accordingly and assigned to a fold based on the size of the first trail. Parameters such as the chosen window lengths determine how many pairs are generated.

Prior to pairing, each trail is normalised to account for differences in sampling rate and spatial resolution. Segments that contain too few points or that show irregular behaviour are discarded to avoid skewing the distance metrics.
Multiple distance measures are calculated for every pair, including Euclidean, Manhattan, cosine, Chebyshev, Canberra and Bray–Curtis distances. Optionally the Mahalanobis distance can also be computed if an inverse covariance matrix is provided. These metrics capture different aspects of similarity between the trails.

Distances are computed not only between the centroids but also across the trajectories themselves. This provides a more nuanced view of similarity, capturing both local and global patterns of movement.
The core routine processes each pair by applying optional outlier treatment, scaling the features, selecting a subset of features and reducing the dimensionality using either LDA, PCA or UMAP. Once both trails are projected into a common space, distances are calculated between their centroids. For each pair, the mean and median distances across all individual points are summarised.

To manage the potentially large number of pairs, processing is parallelised across multiple CPU cores. A progress indicator informs the user about the current status, which helps when evaluating many parameter combinations.
The computation can be executed in parallel with progress reporting. The resulting records store all parameter settings, the distance metrics, optionally predicted sex probabilities and the coordinates of both trails together with those of the reference set.

The final dataset of distances and parameters can be used directly for downstream classification tasks. Because all processing steps are logged, experiments can be replicated or extended with ease.
## Methodik: Pairwise-Identifikations-Pipeline (Deutsch)
Diese Pipeline prüft, ob zwei Bewegungsbahnen vom selben Tier stammen. Zu diesem Zweck werden pro Tier nicht überlappende Abschnitte ausgewählt und zu Paaren kombiniert, sowohl innerhalb eines Individuums als auch zwischen verschiedenen Individuen. Jedes Paar erhält ein Kennzeichen, ob es sich um dasselbe Tier handelt, sowie eine Fold-Nummer basierend auf der Länge des ersten Trails. Die Parameter zur Abschnittslänge, den möglichen Trailgrößen und der maximalen Trailzahl pro Tier steuern die Menge der erzeugten Paare.

Vor dem Kombinieren werden die einzelnen Bewegungsbahnen normalisiert, damit Unterschiede in der Auflösung keinen Einfluss auf die spätere Auswertung haben. Abschnitte mit zu wenigen Punkten oder ungewöhnlichen Mustern werden aussortiert.
Für jedes Paar werden mehrere Distanzmaße bestimmt: Euklidische Distanz, Manhattan-, Cosinus-, Chebyshev-, Canberra- und Bray–Curtis-Distanz. Wenn eine inverse Kovarianzmatrix vorliegt, kann zusätzlich die Mahalanobis-Distanz berechnet werden. Diese Metriken ermöglichen es, globale und lokale Unterschieden der Trajektorien zu erfassen.

Die Distanzen werden nicht nur zwischen den Mittelpunkten der Trajektorien berechnet, sondern auch entlang des gesamten Verlaufs. Dadurch lassen sich sowohl lokale als auch globale Ähnlichkeiten erfassen.
Im Hauptschritt wird für jedes Paar optional eine Ausreißerbehandlung vorgenommen, die Daten werden skaliert, es wird eine Teilmenge relevanter Merkmale ausgewählt und schließlich die Dimension mittels LDA, PCA oder UMAP reduziert. Nach der Projektion in denselben Raum werden die Distanzen zwischen den Zentroiden der beiden Trails berechnet und statistische Kennwerte wie Mittel- und Medianabstand festgehalten.

Um die teils enorme Anzahl an Paaren handhabbar zu machen, wird die Verarbeitung auf mehrere Prozessorkerne verteilt. Ein Fortschrittsbalken informiert über den aktuellen Stand, was bei umfangreichen Parameterstudien hilfreich ist.
Die Berechnungen können parallel ausgeführt werden und bieten einen Fortschrittsbalken. Die Ergebnisse enthalten alle Parameter der Durchführung, die ermittelten Distanzen, gegebenenfalls Sex-Wahrscheinlichkeiten sowie die Koordinaten der projizierten Trails mitsamt der Referenzdaten.
Die entstandenen Datensätze können unmittelbar für Klassifikationsaufgaben genutzt werden. Da alle Schritte genau protokolliert sind, lassen sich Ergebnisse jederzeit nachvollziehen und erweitern.
